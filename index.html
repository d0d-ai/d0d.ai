The technology

Read. Optimize. Execute.

Like Spark, a dOd job is a lazy graph of stages cut at shuffles, run as parallel tasks over partitions of any data source. The difference is who plans it. A language model is six orders of magnitude slower than an engine, so it never processes records: it thinks in plans — small, checkable jobs — and agents on every layer turn them into execution at full engine speed, in memory.

01 · READ

Agents read the question and the data

Schema, size and source are answered straight from metadata. Only real data questions become a job.

02 · PLAN

A job, checked twice

The planner writes a plan; the engine validates it and checks it against your question — no invented filters, the right columns, the rows you asked for.

Why dOd

Agents built into the engine, not bolted on

Most AI data tools put a chatbot in front of a database and translate English into SQL. dOd puts the agents inside the engine — on the driver and on every worker.

Agents on every layer

A router and a planner on the driver; an agent on every worker that optimizes the job for the data it holds.

LLM in memory

The model runs inside the engine process — ~90 ms to first token, no API round-trips, no token bills.

No SQL translation

Questions become validated execution plans, not generated SQL. Every answer comes with the plan behind it.

Any source, read in place

Files, object storage, warehouses and SQL databases, through pluggable connectors — and new ones load at runtime. No copies, no pipeline.

Never leaves your VPC

Model, driver and executors all run in your network. Zero prompts or rows go to a third-party AI service.
